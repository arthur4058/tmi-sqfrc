# GeoLife 60 秒低采样率 V2 多随机种子验证

## 结论

V2 三专家融合在三个独立训练随机种子上均同时提升 Accuracy 和
Macro-F1。因此，V2 相对 B0 的提升不是种子 `10086` 的单次偶然结果。

| 指标 | B0 均值 ± 标准差 | V2 均值 ± 标准差 | V2 相对 B0 平均提升 |
|---|---:|---:|---:|
| Accuracy | 68.55% ± 3.50% | 69.76% ± 3.39% | **+1.21 ± 0.25 pp** |
| Macro-F1 | 61.80% ± 2.38% | 63.84% ± 2.86% | **+2.03 ± 0.50 pp** |

三个种子中，V2 的 Accuracy 增量均为正，Macro-F1 增量也均为正。当前
论文主方法应保持为 V2；V8 类别感知融合不并入主结果，因为它没有在独立
测试上全面超过 V2。

## 固定实验协议

- 数据：GeoLife 五档固定采样率视图中的 60 秒档；
- 窗口：300 秒物理时间窗；
- 输入：`50%noise`，与B0和此前V2一致；
- 划分：训练、验证、测试用户互斥；
- 样本数：训练 62,786、验证 7,129、测试 4,918；
- 训练上限：200 epochs，early stopping patience 40；
- 三个专家：B0双分支、4特征专家、7特征运动专家；
- 每个种子均只在验证集进行温度校准和非负融合权重搜索；
- 最终指标由该种子独立测试集计算，测试标签不参与权重选择。

## 验证集选择的融合权重

权重顺序为 `B0 / 4特征专家 / 7特征运动专家`：

| Seed | 验证集确定的权重 |
|---:|---:|
| 10086 | 0.24 / 0.14 / 0.62 |
| 42 | 0.68 / 0.10 / 0.22 |
| 2024 | 0.42 / 0.30 / 0.28 |

权重随训练随机性变化，说明不能把单次实验的固定权重直接推广到所有训练
实例；但每次都用用户互斥验证集选择权重后，V2在三次独立测试上均取得
提升。这支持“验证集校准的低采样率多专家融合”这一设计，而非某个固定
权重组合。

## 结果解读

1. **提升稳定**：三个种子下V2均优于相同种子的B0，尤其Macro-F1平均
   提升超过2个百分点。
2. **基础模型有明显方差**：B0 Accuracy标准差约3.50个百分点。论文中
   不能只报种子10086的72.49%，应主报均值±标准差，并将单种子结果列为
   补充材料。
3. **V2没有消除训练方差**：V2的Accuracy标准差仍约3.39个百分点；它
   改善的是稀疏窗口的证据融合，不是优化器稳定化方法。
4. **主张边界**：现有结果支持“V2在60秒低采样率下稳定优于B0”，不支持
   “V2在任何采样率、任何数据集下均最佳”的泛化结论。

## 可复现命令

已有种子10086的回归检查：

```bash
python -m scripts.evaluate_three_expert_consensus --rate 60 --seed 10086
```

训练并评估新的种子，例如42和2024：

```bash
python -m scripts.run_v2_multiseed --seeds 42 2024
```

脚本对每个种子按固定顺序执行：

1. 训练B0；
2. 训练4特征专家；
3. 训练7特征运动专家；
4. 用验证集确定温度和权重；
5. 对独立测试集评估并保存JSON结果。

若对应的 `model_best.pth` 已存在，训练脚本会跳过该模型，适合因意外中断
后的安全续跑。

## 后续建议

当前不应继续基于这三个测试集调融合权重或选择新模块，否则会产生测试集
过拟合。下一步应为：

1. 固定V2结构、各超参数和验证集权重搜索规则；
2. 可选补充两个新随机种子，使结果达到5个种子；
3. 统计每类别F1、参数量和推理时间；
4. 在完全相同的用户互斥、300秒窗口、60秒采样协议下，与代表性的低采样
   率交通方式识别方法进行比较。
